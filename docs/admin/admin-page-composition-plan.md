# 관리자 페이지 구성 계획

작성일: 2026-07-06  
대상: P2 관리자 상품 운영 화면  
범위: 화면 구성, 필수/선택 기능, 셀러 상품 등록 자동화 가능성

## 결론

P2 관리자 페이지는 전체 쇼핑몰 운영 관리자 전체 기능이 아니라, 상품 운영자가 P2 데모와 QA에 필요한 상품 상태를 빠르게 확인하고 보정할 수 있는 화면으로 잡는다.

우선순위는 다음과 같다.

1. 상품 조회와 상태 확인
2. 엑셀 기반 상품 대량 등록
3. 이미지 대량 등록
4. 성분 매핑 검수
5. 재고/가격 확인
6. 주문/결제 상태 확인

셀러가 올린 엑셀은 구조화된 데이터이므로 자동 등록이 가능하다. 다만 성분은 표준 성분명과 정확히 매칭되는 항목만 자동 연결하고, 애매하거나 미확정인 값은 pending 상태로 남겨 관리자 검수 대상으로 둔다.

상품 이미지에서 전성분을 OCR로 추출하는 기능은 기술적으로 가능하지만 P2 필수 기능은 아니다. OCR 결과는 오인식 가능성이 있으므로 바로 상품 성분으로 확정하지 않고, P3의 선택 기능 또는 검수 보조 기능으로 둔다.

## 참고한 관리자 구조

NHN 커머스 고도몰 관리자 문서는 관리자 메인에서 주문 상태, 게시글, 통계, 운영 메모, 주요 일정처럼 처리해야 할 일을 한 화면에서 확인하는 구조를 안내한다. 또한 상품, 주문/배송, 회원, 게시판, 통계 등 대메뉴를 통해 운영 기능을 나눈다.

NHN 커머스 샵바이 enterprise 상품관리 문서는 상품정보 조회/수정, 상품등록, 상품심사, 상품재고관리, 상품 일괄 수정, 상품이미지 대량등록 관리 같은 상품 운영 메뉴를 별도로 둔다.

샵바이 상품등록 문서 기준으로 상품은 일반 상품, 세트 상품, 대량 상품 등록으로 나뉘며, 대량 상품 등록은 엑셀 양식 파일을 통해 상품을 일괄 등록하는 방식이다. 대량 등록 결과는 성공/실패 건수로 확인하고, 실패 건이 있으면 실패 결과 엑셀을 내려받아 원인을 확인하는 구조다.

상품이미지 대량등록은 파일명 또는 이미지 항목과 파일명 규칙을 통해 상품번호나 상품관리코드와 이미지를 연결하는 방식이 일반적이다.

대한화장품협회 성분사전은 전성분 표시에 사용하는 표준화 명칭을 제공한다. 따라서 성분 자동 등록은 셀러 입력값을 그대로 확정하는 방식이 아니라 표준 성분명과 대조하고, 매칭 실패 또는 충돌 항목은 검수 대상으로 분리해야 한다.

## 화면 구성안

### 1. 관리자 대시보드

목적: 관리자가 오늘 처리해야 할 상품 운영 상태를 한눈에 본다.

필수 항목:

- 전체 상품 수
- 추천 가능 상품 수
- 판매중/검수필요/품절임박 상품 수
- 이미지 누락 상품 수
- 성분 매핑 검수 대기 수
- 최근 주문/결제 상태 요약
- 최근 import job 상태

현재 `/admin` 1차 화면은 이 영역을 먼저 구현한 정적 UI 초안이다.

### 2. 상품 조회/수정

목적: 상품명, 브랜드, 상품 ID, 판매 상태로 상품을 찾고 기본 운영 정보를 확인한다.

필수 항목:

- 상품 ID
- 상품명
- 브랜드
- 판매 상태
- 재고
- 판매가
- 마지막 수정 시각
- 검수 상태

선택 항목:

- 노출 여부
- 추천 가능 여부
- 이미지 개수
- 성분 매핑 상태
- 검색/추천 인덱스 반영 상태

### 3. 상품 등록

목적: 소량 상품을 직접 등록하거나 수정한다.

P2 필수:

- 상품명
- 브랜드
- 카테고리
- 가격
- 재고
- 판매 상태
- 대표 이미지
- 전성분 텍스트 입력

P3 선택:

- 옵션/구성 상품
- 판매 기간
- 프로모션
- 배송 템플릿
- 상품정보고시 상세 편집

### 4. 엑셀 대량 등록

목적: 셀러가 여러 상품을 한 번에 등록한다.

P2 필수 흐름:

1. 엑셀 템플릿 다운로드
2. 셀러가 상품 정보 입력
3. 엑셀 업로드
4. 컬럼 검증
5. 상품 기본정보 임시 저장
6. 성분명 표준 매칭
7. 성공/실패 결과 표시
8. 실패 결과 파일 다운로드

필수 검증:

- 필수 컬럼 누락
- 상품 ID 또는 seller SKU 중복
- 가격 숫자 형식
- 재고 숫자 형식
- 이미지 파일명 참조 존재 여부
- 전성분 텍스트 존재 여부
- 표준 성분명 매칭 성공/실패

P2에서는 실패 항목을 자동 무시하지 않고 import result로 분리한다.

### 5. 이미지 대량 등록

목적: 상품 이미지 파일을 상품과 연결한다.

P2 필수 방식:

- 파일명 규칙 기반 연결
- 예: `product_code_main.jpg`, `product_code_01.jpg`
- 이미지 업로드 결과 성공/실패 표시
- 매칭 실패 파일 목록 표시

P2에서는 이미지에서 성분을 자동 추출하지 않는다.

P3 선택:

- 상세 이미지 OCR
- 패키지/라벨 이미지 OCR
- OCR 결과와 엑셀 성분 텍스트 비교
- OCR confidence가 낮은 항목 검수 대기 처리

### 6. 성분 매핑 검수

목적: 셀러 입력 성분을 내부 표준 성분과 연결한다.

P2 필수:

- 엑셀 전성분 텍스트 파싱
- 쉼표, 슬래시, 줄바꿈 기준 분리
- 대한화장품협회 성분사전 또는 내부 `ingredients.csv` 기준 exact match
- exact match 성공 시 자동 연결
- 실패 시 `ing_pending_*` 또는 `foreign_pending_*` 상태로 보관
- 관리자가 pending 성분을 확인할 수 있는 목록 제공

P2에서 자동 확정 가능한 경우:

- 입력 성분명이 내부 표준 성분명과 정확히 일치
- 입력 영문명이 내부 표준 영문명과 정확히 일치
- 기존 alias 테이블에서 accepted 상태인 별칭과 일치

P2에서 자동 확정하면 안 되는 경우:

- 부분 일치
- 유사도만 높은 경우
- OCR로만 추출된 경우
- 복합 성분 또는 원료 상품명이 섞인 경우
- 기능성 표현이나 효능 판단이 필요한 경우

P3 선택:

- alias 승인/거절 워크플로
- 성분 후보 추천
- OCR 기반 성분 후보 추출
- 대한화장품협회 표준화명칭목록 다운로드 파일 기반 주기적 갱신

## 필수/선택 기능 분류

| 영역 | P2 필수 | P3 선택 |
| --- | --- | --- |
| 관리자 대시보드 | 상품/주문/검수 요약 | 개인화 위젯, 알림 설정 |
| 상품 조회 | 검색, 필터, 상태 확인 | 컬럼 커스터마이즈 |
| 상품 등록 | 단건 등록, 기본정보 입력 | 옵션/프로모션/배송 템플릿 고도화 |
| 엑셀 대량 등록 | 템플릿, 업로드, 검증, 실패 결과 | 재시도/rollback, 예약 import |
| 이미지 등록 | 파일명 규칙 기반 대량 매칭 | OCR, 이미지 품질 검사 |
| 성분 매핑 | exact match 자동 연결, pending 검수 | alias 승인 워크플로, OCR 보조 |
| 재고/가격 | 조회와 간단 수정 | 이력, 예약 변경 |
| 주문/결제 | 상태 조회 | 클레임/환불/교환 |
| QA/리포트 | import 실패, 성분 pending 수 | 자동 알림, 일별 리포트 |

## 자동 등록 가능성 판단

### 엑셀 업로드

가능하다.

이유:

- 상품명, 브랜드, 가격, 재고, 판매 상태, 전성분 텍스트는 구조화된 컬럼으로 받을 수 있다.
- 현재 프로젝트도 CSV/seed 기반 데이터 구조를 사용하므로 엑셀을 CSV로 변환해 검증하는 흐름과 잘 맞는다.

단, 전부 자동 확정은 아니다.

- 상품 기본정보는 필수값과 형식이 맞으면 자동 등록 가능
- 가격/재고는 숫자 검증 후 자동 등록 가능
- 이미지는 파일명 규칙이 맞으면 자동 연결 가능
- 성분은 표준명 exact match까지만 자동 연결
- 성분 불일치, 중복, OCR 추출값은 검수 대기

### 이미지 업로드

부분적으로 가능하다.

가능한 것:

- 파일명 규칙으로 상품과 이미지 자동 연결
- 대표 이미지와 상세 이미지 구분
- 실패 파일 목록 표시

바로 자동 확정하면 안 되는 것:

- 이미지 속 전성분 OCR 결과를 성분으로 확정
- 패키지 문구를 효능/기능성 근거로 확정

### OCR 성분 추출

P3 선택 기능으로 가능하다.

권장 흐름:

1. 상품 라벨/상세 이미지 업로드
2. OCR로 전성분 후보 추출
3. 텍스트 정제
4. 내부 표준 성분명과 매칭
5. confidence와 매칭 결과 표시
6. 관리자가 승인
7. 승인 후 상품-성분 매핑 반영

P2에서는 OCR을 자동 등록 기능이 아니라 검수 보조 기능으로만 취급한다.

## 현재 `/admin` 화면과의 연결

현재 구현된 `/admin` 1차 화면은 다음 P2 필수 기능의 시작점이다.

- 관리자 대시보드
- 상품 조회
- 처리 대기
- 데이터 상태
- CSV 업로드 진입점
- 상품 등록 진입점

후속 화면은 아래 순서로 붙인다.

1. 상품 조회 리스트를 실제 API와 연결
2. 엑셀 업로드 화면 추가
3. import result 화면 추가
4. 성분 pending 검수 화면 추가
5. 이미지 대량 등록 화면 추가

## 팀 확인 질문

- 추천안: P2는 엑셀 업로드 기반 자동 등록과 파일명 기반 이미지 연결까지 구현한다.
- 대안: P2는 관리자 대시보드와 상품 조회만 두고, 엑셀/OCR은 P3로 미룬다.
- 왜 중요한지: 셀러 상품 등록 방식이 정해져야 관리자 화면, 데이터 계약, seed/import job, 성분 검수 흐름이 충돌하지 않는다.
- 선택 후 영향: 엑셀 업로드를 P2에 포함하면 백엔드 import job과 실패 리포트 화면이 필요하다. OCR까지 포함하면 AI/OCR 비용, 검수 UI, 오탐 처리 기준이 추가로 필요하므로 P3로 두는 것이 안전하다.
