# 추천 점수 3일 진단 결산 (2026-07-19)

> **문서 전용 — 코드·가중치·seed·DB 변경 없음.** 3일간의 추천 점수 개선 시도 결과와 진단, 고도화 백로그를 팀에 공유하기 위한 기록이다. 전체 실험 이력은 `eval_harness_v1/eval_harness/results/experiment_log.jsonl`에 사전등록→결과→정정→결정 순으로 봉인되어 있다.

## 결론 (TL;DR)

**프로덕션 추천 로직·가중치·seed·DB는 현행 유지한다.** 일주일 남은 목업 단계에서 "안전하면서 효과가 입증된" 변경은 없다는 것을 확인했다. 시도했던 코드 PR(#527, #528)은 위험 대비 이득이 불명확하여 닫았고, 발견한 내용은 아래 백로그로 넘긴다.

3일의 산출물은 "점수를 올리는 마법 숫자"가 아니라 **시스템이 왜 개선이 어려운지에 대한 구조 진단**이다.

---

## 1. 핵심 진단

### 1.1 [P0] 효능·근거·함량 축이 조용히 죽는 구조 결함

- **증상:** 데이터 디렉터리에서 `concern_to_effect.json`이 `tags.json`과 다른 위치로 갈려 로드되면, 옛 효과 어휘(`effect_sebum_control`, `effect_texture` 등)가 쓰인다. 이 코드들은 채점 효과 택소노미 6종(`effect_acne_sebum`·`effect_brightening`·`effect_calming`·`effect_exfoliation`·`effect_moisture_barrier`·`effect_wrinkle`)에 존재하지 않아, desired_effects 조회가 0건이 되고 **효능·근거·함량 3개 점수축이 기본값(0.5/0)으로 죽는다.**
- **범위:** 순정 `dev`에서도 재현되는 기존 구조 결함(측정이 처음 밟은 것). LLM 파서가 정상 작동하면 올바른 코드를 산출하므로 프로덕션 주경로는 무사할 가능성이 높다. 위험은 키워드 폴백 경로(LLM 부재/실패)와 데이터 마운트 오류.
- **확인 필요:** 배포 `DATA_DIR`에 `concern_to_effect.json`이 `tags.json`과 같은 디렉터리에 있는지. 있으면 프로덕션 무해로 종결.

### 1.2 [핵심] 리뷰 파생 정답셋은 성분과학 축을 구조적으로 "벌준다"

- **격리 실험:** `concern_to_effect.json` 한 파일만 바꿔(효과축 죽음 ↔ 살아남) 동일 조건으로 dev83을 측정. 효과·근거·함량 축을 **살리자 모든 리뷰 심판 점수가 대폭 하락**(실버 top50 50→38, v3 리뷰 top10 49%→23%, v4 합의 top10 77%→52%, 79/83 질문 순위 이동).
- **해석:** 리뷰 파생 정답셋(실버·v3·v4)은 "리뷰가 좋아한 상품 = 정답"이다. 효과축을 켜면 성분과학적으로 적합한 상품이 인기 상품을 밀어내 심판과 어긋난다. **즉 우리 평가셋으로는 성분과학 층의 좋고 나쁨을 판정할 수 없다.**
- **함의:** 이 프로젝트의 dev83 측정 상당수가 효과축이 죽은 환경(1.1)에서 수행됐고, 프로덕션(효과축 살아있음 추정)과는 다른 시스템을 잰 것이다. "지표가 안 오른다"의 진짜 원인은 배점이 아니라 평가셋의 성격이다.

### 1.3 함량 데이터: 미배선 + 채워도 지표 무효과

- 확충 함량 추정치(`data/reconciliation/concentration_coverage_estimates.csv`, 약 48,000행)가 코드 어디에서도 읽히지 않아 함량 축이 사실상 상수였다.
- 로컬 클론에 고신뢰 추정치(4,096개)를 주입하고 재롤업한 결과: 함량 보유 상품 919→1,251개로 축은 살아났으나, **추천 순위 지표는 무변동(무승부).** LLM-on·정품 마운트 등 3가지 방식으로 교차 확인.
- 가치는 함량 경고·투명성·콜드스타트이지 순위 개선이 아니다.

### 1.4 가중치 튜닝: 안전하게 입증된 승자 없음

- 검색 가중치 상향 등 다수 실험을 진행했으나 유의한 개선이 입증되지 않았고(검색35는 정답지 중복으로 철회), **봉인 테스트셋이 소진되어 새 가중치를 독립 검증할 수단이 없다.**
- → 프로덕션 가중치 현행 유지가 결론.

## 3. 고도화 백로그 (런칭 후 검토)

1. **[지운/세민] 배포 DATA_DIR 점검** — `concern_to_effect.json`이 `tags.json`과 같은 디렉터리에 있는지 확인. P0 결함(1.1)의 프로덕션 영향 여부 종결.
2. **[규태] 효과축 어휘 가드** — 데이터 불일치가 조용히 통과하는 것을 막는 검증. 닫은 PR #527이 근거·초안.
3. **[세민/규태] 함량 배선** — 추정치 출처 표식 + 과다-경고 억제 설계 선행 후 재검토. 닫은 PR #528 + `RESULT_conc_data_ab`가 근거.
4. **[규태] P0 성분 매핑 반영** — primary·미검증 5개(특히 Sodium Acetylated Hyaluronate→주름) 사람 검수 후 클론 검증.
5. **[현옥/규태] 평가셋 신설(가장 근본)** — 리뷰 파생 정답셋으로는 성분과학 층을 판정할 수 없음(1.2). 사람 패널 또는 실사용 행동 A/B 평가 설계 필요.

## 4. 신뢰 경계

- 모든 측정은 개발 결과(같은 dev를 반복 관측한 프록시 관측치)이며 정답셋은 자동 프록시(사람 채점 없음).
- 읽기 전용 감사·로컬 클론 기준. 프로덕션 코드·데이터·공유 DB·가중치는 변경하지 않았다.
- 봉인 평가셋 소진, 비회원 replay 한정 등 한계는 `experiment_log.jsonl` 및 `stage2/` 문서에 기록.

## 역할별 영향 범위

이 PR은 **문서 추가 전용**이다. 런타임 코드·API·데이터 계약·가중치·seed·DB·환경변수 변경이 없으므로 **동작상 영향은 없다.** 다만 각 역할이 내용상 확인할 부분은 아래와 같다.

- **현옥 PM/UX:** 추천 개선이 이번 단계에서 반영되지 않는 이유와, 근본적으로 "리뷰 기반 평가로는 성분과학 품질을 못 잰다"는 결론(§1.2). 향후 평가 기준 설계 시 참조.
- **지현 프론트엔드:** 영향 없음. 화면·응답 스키마 무관.
- **원우 백엔드:** 영향 없음. Auth/Order/재고 무관. §1.1의 데이터 로딩 결함은 추천 파이프라인 한정.
- **규태 AI 추천/검색/에이전트:** 핵심 독자. §1(전체 진단)·§3(백로그 2·3·4)의 소유자. 닫은 PR #527/#528의 코드·근거가 백로그 재개 시 출발점.
- **세민 데이터:** §1.1(concern_to_effect.json·tags.json 짝 유지)·§1.3(함량 추정치 CSV)·§3(백로그 1·3). 데이터 디렉터리 패키징·seed 시 참조.
- **지운 인프라/로그:** §3 백로그 1(배포 DATA_DIR 점검)의 소유자. 그 외 배포·CI 직접 영향 없음.
