# 뭐바를래 추천 점수 설계 — scoring-design

> 대표님(규태) 추천 점수 설계의 스냅샷. **효능 산출은 곱셈, 최상위 결합은 가중 가산**의 2층 구조.
> 근거(논문) 규칙은 같은 폴더 `evidence-policy.md` 참조 — evidence_trust·effect_strength가 이 점수식에 곱해진다.
> **정본은 `docs/scoring/source/` 의 엑셀 원본.** 이 문서는 그 설계를 읽기 쉽게 옮긴 스냅샷이며, 세부 수치는 엑셀이 정본이다.

---

## 한눈에

성분 하나의 점수를 **효능강도 × 근거신뢰도 × 적용성 × 규제 × 함량 × 함량신뢰도**로 곱해서 만든다(더하지 않고 깎는다). 성분을 축별로 모아 제품 점수를 내고(주70/보조30, noisy-OR), 마지막에 4개 항목(효능·근거·피부타입·가격)을 가중 합산해 0~100 총점을 낸다.

---

## 1. 점수축 — 성분 × 6축

정본 6축: **미백·톤 / 주름·탄력 / 여드름·피지 / 보습·장벽 / 진정 / 각질**
(사용자 표준 피부고민 12개 → 6축 매핑은 `evidence-policy.md §1` 참조.)

**설계 방향 — 정본 6축은 팀 파서 스키마(`concern_parser_output_schema.json`)를 따른다.** 보습·장벽 병합 + 각질 포함의 6축이 계약이고, 계산 코드는 이 스키마에 맞춘다(현재 어긋난 부분은 §7). 화면·API도 이 6축으로 나간다. 중고도화에서 한 축의 내부를 더 잘게 계산하고 싶을 때(예: 보습·장벽을 내부적으로 수분 / 장벽으로 나눠 데이터를 쌓되, 화면엔 `수분 80·장벽 45` → `보습·장벽 63`처럼 6축으로 합쳐 보여줌)도 **스키마 6축을 계약으로 유지한 채 내부 구현만 정교화**하고, 검증되면 팀 합의로 정식 승격한다. 스키마를 벗어나지 않는다.

**⚠ 관찰된 불일치 (코덱스 확인):** 파서 스키마(`concern_parser_output_schema.json`)의 6축은 보습·장벽 병합 + 각질 포함인데, repo 계산 코드는 보습/장벽 분리 + **각질 제거**로 갈려 있다. **본 설계(스코어링_마스터)는 각질을 정식 축으로 유지**한다(각질 = 고민 C08 + roughness/scaling 지표 + AHA·PHA 성분). 따라서 계산 코드의 각질 제거는 설계 결정이 아니라 드리프트로 보이며, 그대로 두면 AHA·PHA 점수 경로가 통째로 사라진다. → §7 참조.

## 2. 성분 단위 점수 (곱셈)

| 단계 | 공식 | 범위 |
|---|---|---|
| rule_weight | effect_strength × evidence_trust | 0~1 |
| 조정 rule_weight | rule_weight × applicability × regulatory | 0~1 |
| **성분기여점수** | 조정 rule_weight × 함량점수 × 함량신뢰도 | 0~1 |

원칙: **더하지 않고 곱해서 깎는다.** 근거가 강한 것과 효과가 큰 것은 분리한다(evidence_trust ↔ effect_strength). 신뢰도 이중계산 금지.

### 2.1 effect_strength (효과강도)
논문 효과크기에서 뽑은 0~1 초안값. 예: 나이아신 0.7 · 레티날 0.72 · 트라넥사믹 0.72 · 알부틴 0.6 · 코직 0.45. **⚠ 초안값 — 함량 기준·실제 효과크기 확인 후 다음 버전에서 보정.**

### 2.2 evidence_trust (근거신뢰도) — 연구유형으로 자동
| 연구유형 | trust | 등급 |
|---|---|---|
| 가이드라인 / 식약처 / Regulatory | 0.95 | A |
| 메타 / SR / Cochrane | 0.90 | A |
| RCT / double-blind | 0.85 | A |
| 일반 임상 | 0.80 | B |
| 일반 리뷰 | 0.75 | B |
| 안전성 / CIR | 0.60 | C |
| 세포 / 동물 / in vitro | 0.45 | C |

고시 성분은 연구유형이 아니라 고시로 신뢰도를 준다(et_산정근거유형 분리).

### 2.3 applicability · regulatory
- **applicability(적용성)** 0~1 — 도포·화장품 맥락 적합도. 경구·주사·필링은 낮춤.
- **regulatory(규제)** 0~1 — 규제/안전 반영. 고시형 별도, 안전 확인중은 0.5 등.

### 2.4 함량점수 · 함량신뢰도
| 경우 | 함량점수 | 함량신뢰도 |
|---|---|---|
| 함량 공개 | 성분별 변환표 0~1 (상한 초과는 가산 안 함) | 높음 |
| 함량 미공개 | 보수값 | 0.2~0.5 (전성분 상위 → 0.5) |
| 고시 앵커 성분 | min 도달 0.6 / full 도달 1.0 | — |
| 비고시 성분 | 문헌·시장·전문가 임시 범위 (초안 명시) | — |

발표용 한 줄: **논문은 성분의 자격을, 함량은 제품에서 그 효과가 실현될 가능성을 증명한다.**

## 3. 제품 단위 점수 (축별)

1. **그룹 분리** — score_use_level로: PRIMARY(주성분) / SUPPORT(보조) / REFERENCE(참고 = 점수 제외)
2. **그룹 내 합산 (noisy-OR)** — `combined = 1 − Π(1 − 성분기여점수)`. 성분이 늘수록 오르되 완만해짐.
3. **상한** — `primary_score = primary_combined × 70`, `support_score = support_combined × 30`
4. **축별 제품점수** — `axis_score = MIN(100, primary_score + support_score)` → 0~100

주70/보조30: 주성분 영향력 상한 70, 보조 상한 30.

---

## 4. 개인화 · 시장검증 보정

- **개인화** — 피부타입(건성/지성/복합성/수부지/중성 5종) × 민감도(3단계) × 회피성분. 회피는 **하드 제외**, 위험수준은 **감점**. 효능과 적합/안전을 분리.
- **시장검증(리뷰)** — 리뷰수·평점·구매수 → Bayesian/신뢰도 보정. **효능 근거가 아니라 시장 검증.** → **MVP 제외**(상품근거·리뷰매칭은 후속).

---

## 5. 최상위 총점 · 정규화 (9단계)

①각 평가항목 0~1 정규화 → ②효능별 top3 성분 감쇠 1.0/0.5/0.25 → ③효능별 cap=1.2 (`min(원점수/1.2, 1.0)`) → ④고민-효능 가중치로 합산 → ⑤성분효능 소점수 0~1 clamp → ⑥상품근거·리뷰매칭 제외(MVP) → ⑦ **총점 = (성분효능 × 0.45 + 성분근거 × 0.35 + 피부타입매칭 × 0.15 + 가격구매 × 0.05) × 100 − 위험성분감점** → ⑧위험성분감점 최대 −15 → ⑨최종 0~100 clamp

즉 §2~§3의 곱셈으로 만든 **성분효능**이 여기서 0.45 가중치로 최상위 가산에 들어간다. (곱셈=효능 산출 층, 가산=최상위 결합 층.)

**재현성:** LLM은 자연어 → 표준 고민/효능 변환에만 쓰고, 이후 점수는 결정적 코드. 추천 결과는 24h 캐시 → 재조회 시 동일(새로고침·상세·데모 고정).

---

## 6. score_use_level (주/보조/참고) 산출

기본 = 주점수. 강등조건마다 1단계 강등.
- **강등 (각 1단계):** route_mismatch · concentration_mismatch · indirect_or_complex_formula · non_pubmed_source_check → 0개=주 / 1개=보조 / 2개+=참고
- **하드규칙 → 참고만:** preclinical_only · safety_only · pdrn_topical_evidence_limited
- **예외 → 주점수 가능:** 식약처 기능성 고시 성분

상세는 `evidence-policy.md §4.2`.

## 7. 미해결 / 팀 리뷰 안건

1. **⚠ 안전·개인화 결합 방식 + 스케일 통일** — 최상위 ⑦은 위험을 **감점**(−위험성분감점, 최대 −15)으로, 스코어링_마스터는 **곱**(제품점수 × 개인민감보정)으로 처리한다. 또 마스터의 `axis_score(0~100)`와 ⑦의 `성분효능 소점수(0~1)` **스케일 정합**을 맞춰야 한다. 둘 중 하나로 정본 확정 필요. *(효능=곱셈, 최상위=가산 자체는 상충 아님. 통일할 것은 안전 처리 방식과 스케일.)*
2. **6축 정의 통일 — 팀 스키마를 정본으로** — 스키마(보습·장벽 병합 + 각질 포함) vs 계산 코드(보습/장벽 분리 + 각질 제거). **정본은 팀 파서 스키마 6축.** 계산 코드의 드리프트(각질 제거·보습장벽 분리)를 스키마에 맞춰 복구한다 — 각질 축·AHA/PHA 경로를 되살리고, 보습·장벽은 병합 유지.
3. **effect_strength 초안값** → 함량·효과크기 확인 후 보정.
4. **웹보강 논문** (코직2% RCT · 알란토인6% Phase3 · Zinc PCA 1% 등) PMID 스크립트 재검증.
5. **시장검증(리뷰) 보정** = MVP 이후 도입.
6. **정규화 세부 파라미터** (감쇠 1.0/0.5/0.25, cap 1.2, 가중치 45/35/15/5) 실데이터로 튜닝.
