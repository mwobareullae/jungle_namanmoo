# 뭐바를래 최종 라이브 데모 시나리오

## 1. 데모 개요

- 총 시간: 5분
- 데모 성격: 쇼핑몰 전체 사용자 흐름 안에서 AI 추천과 쇼핑 에이전트가 자연스럽게 연결되는 과정을 시연한다.
- 데모 종료 지점: 주문서 확인 화면
- 제외 범위: 결제 실행, 주문 완료, 커뮤니티 전체 기능

### 데모 목표

사용자가 평소처럼 피부 고민을 입력하고 상품을 살펴보다가, 선택이 어려운 순간에 에이전트의 도움을 받는 흐름을 보여준다. 에이전트는 별도의 챗봇 서비스처럼 동작하지 않고 현재 상품과 직전 대화를 이해해 비교, 장바구니 반영, 주문서 이동을 실행한다.

### 핵심 메시지

> 뭐바를래는 피부 고민을 상품 검색어로만 처리하지 않습니다. 피부 타입과 성분 근거를 바탕으로 상품을 추천하고, 선택이 어려운 순간에는 AI 에이전트가 현재 쇼핑 맥락을 이어받아 비교부터 다음 화면 이동까지 도와줍니다.

### 데모 원칙

1. 쇼핑몰이 주인공이고 에이전트는 필요한 순간에만 개입한다.
2. 추천 결과보다 추천 근거와 선택 이유를 함께 보여준다.
3. 에이전트는 채팅 답변에서 끝나지 않고 실제 API와 화면 동작을 실행한다.
4. 상품 선택은 사용자가 결정한다.
5. 결제와 최종 제출은 사용자가 검토한 뒤 직접 실행하도록 남겨둔다.

## 2. 데모 전 필수 준비

라이브 데모 시작 전에 아래 항목을 반드시 확인한다.

### 계정과 데이터

- 로그인 상태를 유지한다.
- 데모 계정에 피부 프로필을 저장한다.
  - 권장 피부 타입: `복합성`
  - 권장 민감도: `보통` 또는 `높음`
- 장바구니를 비우거나, 시작 수량을 미리 기록한다.
- 데모 계정의 등록 배송지를 비운다.
- 공개 가능한 데모용 수령인·연락처·주소를 준비한다.
- 개인 실거주지나 개인 연락처는 라이브 화면에 입력하지 않는다.
- 실제 상품·가격·재고 API가 정상인지 확인한다.
- `OPENAI_API_KEY`, 에이전트 모델, 백엔드 연결 상태를 확인한다.
- Mock 데이터나 Mock 결제는 사용하지 않는다.

### 추천 상품 사전 확인

본 시연에서 사용할 추천 상품은 발표 당일 실제 API 결과로 선정한다. 다음 조건을 만족해야 한다.

- 상품 이미지가 정상적으로 노출된다.
- 판매 중이고 재고가 있다.
- 가격이 표시된다.
- AI 추천 요약이 표시된다.
- 추천 근거 또는 점수 분석 데이터가 있다.
- 에이전트가 비슷한 상품을 2개 이상 찾을 수 있다.

조건을 만족하지 않으면 다른 추천 상품을 선택한다. 특정 상품 ID를 발표 자료에 고정하지 않는다.

### 브라우저와 화면

- 브라우저 탭은 한 개만 사용한다.
- 시작 화면은 홈(`/`)으로 둔다.
- 화면 확대 비율과 해상도는 사전에 고정한다.
- 개발자 도구, 관리자 화면, 로그 창은 관객에게 노출하지 않는다.
- 네트워크와 백엔드를 재시작한 경우 로그인과 에이전트 응답을 다시 확인한다.

### 1회 리허설 체크

아래 다섯 문장을 순서대로 입력해 실제 응답을 확인한다.

1. `이 상품과 비슷한 상품 2개 보여줘.`
2. `첫 번째 상품이랑 지금 보고 있는 상품을 비교해줘.`
3. `지금 보고 있는 상품을 장바구니에 담아줘.`
4. `이 장바구니로 주문서 열어줘.`
5. `받는 분 데모 사용자, 연락처 010-1234-5678, 우편번호 06236, 기본 주소 서울특별시 강남구 테헤란로 123, 상세 주소 4층으로 등록해줘.`

비교 결과가 비어 있거나 맥락 참조가 어긋나면 발표 전에 사용할 추천 상품을 교체한다. 다섯 번째 입력 후에는 배송지 등록 화면으로 따로 이동하지 않아도 주문서 준비가 자동으로 재개되는지 확인한다.

## 4. 장면별 실행 대본

## 장면 1. 홈에서 서비스 소개

### 시간

0:00–0:20

### 화면

홈 화면의 AI 추천 입력 영역을 보여준다.

### 발표자가 그대로 말할 멘트

> 지금부터 사용자가 피부 고민에 맞는 상품을 찾고, 비교가 필요한 순간에는 AI 에이전트의 도움을 받아 주문서까지 이동하는 과정을 보여드리겠습니다. 쇼핑은 기존 화면에서 진행하고, 에이전트는 사용자의 선택이 어려운 순간에만 개입합니다.

### 진행 동작

1. 홈의 `AI 추천` 탭이 선택되어 있는지 확인한다.
2. 피부 고민 입력창을 클릭한다.

### 이 장면에서 강조할 것

- 에이전트 채팅부터 시작하지 않는다.
- 사용자는 일반 쇼핑몰과 동일하게 홈 화면에서 탐색을 시작한다.

---

## 장면 2. 피부 고민 입력

### 시간

0:20–0:55

### 입력할 문장

```text
T존은 번들거리지만 볼은 건조하고, 자극이 적은 진정·보습 제품을 찾고 있어요.
```

### 발표자가 그대로 말할 멘트

> 사용자는 제품명이나 성분명을 알지 못해도 자신의 피부 상태를 자연어로 입력할 수 있습니다. 여기서는 복합성 피부의 유수분 불균형과 자극 부담을 함께 입력하겠습니다.

### 진행 동작

1. 위 문장을 입력한다.
2. 저장된 피부 타입과 민감도가 올바르게 표시되는지 확인한다.
3. `AI 추천 받기`를 누른다.

### 화면에서 확인할 것

- 추천 결과 페이지로 이동한다.
- 로딩 후 실제 추천 상품이 노출된다.
- 추천 점수와 추천 이유가 함께 표시된다.

### 화면이 로딩되는 동안 말할 멘트

> 입력한 문장을 바로 상품명으로 검색하는 것이 아니라, 피부 고민과 필요한 효능을 해석하고 저장된 피부 타입과 민감도를 함께 반영합니다.

---

## 장면 3. 추천 결과와 근거 확인

### 시간

0:55–1:35

### 발표자가 그대로 말할 멘트

> 추천 결과에는 단순 순위만 표시하지 않습니다. 피부 고민과 연결되는 성분, 성분 근거, 피부 타입 적합도, 민감 피부에서 확인할 항목 등을 함께 고려한 결과입니다. 점수 자체보다 어떤 정보가 추천 판단에 사용됐는지를 확인할 수 있습니다.

### 진행 동작

1. 상위 추천 상품의 점수와 추천 이유를 가리킨다.
2. 대표 성분 또는 근거 태그를 짧게 보여준다.
3. 이미지, 가격, 판매 가능한 상태를 확인한다.
4. 사전에 확인한 추천 상품 카드를 클릭한다.

### 설명 시 주의사항

- 공개되지 않은 가중치 수치를 임의로 말하지 않는다.
- 치료, 완치, 효과 보장과 같은 표현을 사용하지 않는다.
- 실제 화면에 없는 리뷰 수, 구매 수, 함량을 말하지 않는다.

### 추천 표현

> 이 상품이 반드시 효과가 있다는 의미가 아니라, 입력한 고민과 현재 확보된 성분·상품 데이터를 기준으로 먼저 검토할 후보라는 의미입니다.

## 장면 4. 상품 상세에서 추천 이유 확인

### 시간

1:35–2:05

### 화면

추천 결과에서 진입한 상품 상세 화면이다.

### 발표자가 그대로 말할 멘트

> 상품 상세에서는 왜 이 상품이 추천됐는지 사용자가 이해할 수 있는 문장으로 다시 보여줍니다. 또한 성분 근거와 민감도 관련 확인 항목을 직접 살펴볼 수 있어, 추천 결과를 그대로 믿는 것이 아니라 구매 전에 검토할 수 있습니다.

### 진행 동작

1. `AI 추천 요약`을 보여준다.
2. 추천 점수 또는 추천 근거 영역을 보여준다.
3. 대표 성분과 주의 정보를 짧게 확인한다.
4. 상품 상세 상단으로 돌아와 현재 상품명과 가격이 보이게 한다.

### 전환 멘트

> 여기까지는 사용자가 직접 탐색하는 일반적인 쇼핑 흐름입니다. 이제 비슷한 상품도 함께 보고 싶지만 하나씩 다시 검색하고 비교하기는 번거로운 상황을 가정하겠습니다.

## 장면 5. 현재 상품을 기준으로 유사 상품 요청

### 시간

2:05–2:40

### 에이전트에 입력할 문장

```text
이 상품과 비슷한 상품 2개 보여줘.
```

### 입력 전에 말할 멘트

> 별도의 상품명을 다시 입력하지 않고, 현재 보고 있는 상품을 그대로 가리켜 요청하겠습니다.

### 응답을 기다리며 말할 멘트

> 에이전트는 현재 페이지의 상품 ID를 전달받아 실제 판매 상품과 재고·가격 정보를 다시 확인합니다.

### 기대 화면

- 에이전트가 현재 상품을 기준으로 유사 상품 2개를 반환한다.
- 상품 이미지, 상품명, 가격, 유사 이유가 표시된다.
- 결과 상품은 실제 상품 상세로 이동할 수 있다.

### 결과가 나온 뒤 말할 멘트

> 지금 나온 결과는 독립적인 검색 결과가 아니라, 방금 보고 있던 상품을 기준으로 찾은 비교 후보입니다.

## 장면 6. 직전 결과와 현재 상품 비교

### 시간

2:40–3:15

### 에이전트에 입력할 문장

```text
첫 번째 상품이랑 지금 보고 있는 상품을 비교해줘.
```

### 입력 전에 말할 멘트

> 이번에는 상품명을 다시 말하지 않고, 직전 결과의 첫 번째 상품과 현재 상품을 비교해달라고 하겠습니다.

### 기대 화면

- 에이전트가 `첫 번째 상품`을 직전 도구 결과에서 찾는다.
- `지금 보고 있는 상품`을 현재 페이지 맥락에서 찾는다.
- 두 상품의 가격, 주요 성분·근거, 민감 피부 고려 사항이 비교된다.
- 비교 UI가 열리고 두 상품 사이의 차이를 확인할 수 있다.

### 결과가 나온 뒤 그대로 말할 멘트

> 이 장면의 핵심은 단순 추천이 아니라 대화와 화면 맥락을 함께 이해한다는 점입니다. 직전 결과의 첫 번째 상품과 현재 페이지의 상품을 다시 검색하지 않고 연결해 비교했습니다.

### 사용자 선택 멘트

비교 결과를 짧게 보고 다음과 같이 말한다.

> 비교해보니 저는 처음 보고 있던 상품이 제 고민에 더 적합해 보여서 이 상품을 선택하겠습니다.

중요: 비교 결과가 첫 번째 후보에 더 유리하게 나왔다고 해도, 발표에서는 점수를 왜곡하지 않는다. 그 경우에는 “가격보다 현재 상품의 성분 구성을 우선해 선택하겠습니다”처럼 사용자의 선호 기준을 명시한다.

## 장면 7. 현재 상품을 장바구니에 반영

### 시간

3:15–3:50

### 에이전트에 입력할 문장

```text
지금 보고 있는 상품을 장바구니에 담아줘.
```

### 입력 전에 말할 멘트

> 추천과 비교가 실제 구매 행동으로 이어지는지 확인하겠습니다. 현재 상품을 장바구니에 담아달라고 요청하겠습니다.

### 기대되는 시각적 실행

1. 에이전트가 현재 상품과 재고·가격을 확인한다.
2. 상품 상세의 장바구니 버튼이 강조된다.
3. AI 커서가 버튼으로 이동한다.
4. 버튼 눌림 효과가 표시된다.
5. 실제 장바구니 API가 실행된다.
6. `장바구니에 담았어요` 알림이 표시된다.
7. 헤더의 장바구니 수량이 증가한다.

### 실행되는 동안 그대로 말할 멘트

> 에이전트가 말로만 담았다고 답하는 것이 아니라, 실제 장바구니 API를 실행합니다. 화면에서는 어떤 UI가 실행되는지 커서와 버튼 강조로 확인할 수 있고, 처리 후 장바구니 수량도 함께 갱신됩니다.

### 결과 확인 멘트

> 방금 선택한 상품이 실제 장바구니에 반영됐습니다.

## 장면 8. 배송지를 등록하고 주문서까지 이동

### 시간

3:50–4:40

### 에이전트에 입력할 문장

```text
이 장바구니로 주문서 열어줘.
```

### 입력 전에 말할 멘트

> 마지막으로 이 장바구니를 기준으로 주문서를 열어달라고 하겠습니다. 이 데모 계정에는 배송지를 미리 등록하지 않았습니다. 필요한 정보가 없을 때 에이전트가 어떻게 확인하고 쇼핑 흐름을 이어가는지도 함께 보겠습니다.

### 기대되는 시각적 실행

1. 실제 장바구니와 구매 가능한 상품을 다시 확인한다.
2. 헤더의 장바구니 아이콘이 강조된다.
3. AI 커서의 클릭 효과 후 장바구니 페이지로 이동한다.
4. 주문할 상품이 선택된 상태로 표시된다.
5. 배송비와 결제 예정 금액이 계산된다.
6. 주문서 준비에 배송지가 필요하다는 사실을 확인한다.
7. 에이전트가 필요한 배송지 항목을 사용자에게 질문한다.

### 이동 중 그대로 말할 멘트

> 에이전트는 곧바로 결제창을 열지 않습니다. 먼저 장바구니에서 실제 상품과 금액을 확인하고, 주문서에 필요한 배송지가 없으면 임의의 정보를 만들지 않고 사용자에게 필요한 항목을 질문합니다.

### 배송지가 없을 때 이어지는 정상 흐름

에이전트가 다음 정보를 요청하는지 확인한다.

```text
등록된 배송지가 없어요. 받는 분 이름, 연락처, 우편번호, 기본 주소와 상세 주소를 알려주세요.
```

이때 발표자는 다음과 같이 말한다.

> 현재 계정에는 등록된 배송지가 없습니다. 에이전트가 실패하거나 임의의 주소를 사용하는 대신, 주문서에 필요한 항목만 구체적으로 요청하고 있습니다. 공개 가능한 데모용 배송지로 이어가겠습니다.

에이전트 입력창에는 사전에 준비한 데모 정보를 다음 형식으로 입력한다.

```text
받는 분 데모 사용자, 연락처 010-1234-5678, 우편번호 06236, 기본 주소 서울특별시 강남구 테헤란로 123, 상세 주소 4층으로 등록해줘.
```

개인 실거주지나 개인 연락처를 라이브 화면에 입력하지 않는다. 입력 후에는 다음 동작을 확인한다.

1. 에이전트가 기존 배송지 API로 실제 배송지를 등록한다.
2. 첫 배송지가 기본 배송지로 지정된다.
3. 장바구니와 결제 예정 금액을 다시 검증한다.
4. 중단됐던 장바구니·주문서 화면 이동을 자동으로 재개한다.
5. 주문서 화면에서 방금 등록한 배송지와 결제 예정 금액이 표시된다.
6. 저장된 최근 대화에는 주소와 연락처 원문 대신 `배송지 정보를 입력했어요.`만 남는다.

등록이 완료되면 다음과 같이 말한다.

> 사용자가 배송지 관리 화면으로 따로 이동하지 않아도 방금 말한 정보가 실제 계정 배송지로 등록됐고, 중단됐던 주문서 이동도 자동으로 이어졌습니다. 주소와 연락처 원문은 에이전트 실행 기록과 저장된 대화 기록에 남기지 않습니다.

## 장면 9. 최종 요약

### 시간

4:40–5:00

### 화면

주문서의 상품 목록, 배송지, 최종 금액이 함께 보이는 위치에 둔다. 결제 버튼은 누르지 않는다.

### 발표자가 그대로 말할 최종 멘트

> 지금까지 사용자는 일반 쇼핑몰처럼 피부 고민을 입력하고 추천 근거와 상품 상세를 직접 확인했습니다. 선택이 어려워진 순간에만 에이전트를 호출했고, 에이전트는 현재 상품과 직전 대화를 이해해 비교를 도왔습니다. 선택 이후에는 실제 장바구니 API를 실행했고, 주문서에 필요한 배송지가 없자 사용자에게 확인해 실제로 등록한 뒤 중단된 흐름을 이어갔습니다. 뭐바를래의 AI는 쇼핑몰을 대체하는 별도 챗봇이 아니라, 사용자가 탐색하고 결정하는 과정의 수고를 줄이는 쇼핑 기능입니다.

### 마지막 한 문장

> 추천에서 끝나는 AI가 아니라, 사용자의 선택을 실제 쇼핑 행동으로 연결하는 것이 뭐바를래의 차별점입니다.

## 5. 발표자가 기억할 핵심 포인트

### 반드시 강조할 것

- 사용자는 쇼핑몰 화면에서 직접 탐색을 시작한다.
- 추천은 피부 고민과 성분 근거를 바탕으로 한다.
- 에이전트는 현재 페이지와 직전 대화를 함께 이해한다.
- 상품과 가격·재고는 실제 백엔드에서 다시 확인한다.
- 장바구니는 실제 API로 변경된다.
- 배송지가 없으면 필요한 정보를 질문하고 실제 배송지로 등록한다.
- 배송지 등록 후 사용자가 같은 요청을 반복하지 않아도 중단된 주문서 흐름을 재개한다.
- 화면 강조와 이동을 통해 AI가 실행하는 대상이 보인다.
- 결제는 사용자가 검토하고 직접 결정한다.

### 말하지 않을 것

- “AI가 알아서 가장 좋은 제품을 결정합니다.”
- “이 제품은 반드시 효과가 있습니다.”
- “AI가 사용자 대신 결제합니다.”
- 화면이나 API에 존재하지 않는 리뷰 수·구매 수·성분 함량
- 공개하지 않는 추천 가중치

### 에이전트의 역할을 설명하는 문장

> 사용자의 결정을 대신하는 것이 아니라, 현재 맥락에 필요한 정보를 찾고 비교하며 사용자가 선택한 행동을 실제 화면에 연결합니다.

## 6. 라이브 데모 실패 방지 대응

### AI 추천 결과가 늦게 나오는 경우

다음 멘트를 사용한다.

> 입력한 피부 고민을 효능과 성분 기준으로 해석하고 실제 상품 데이터와 비교하고 있어 잠시 시간이 필요합니다.

새로고침하거나 같은 요청을 연속으로 전송하지 않는다.

### 유사 상품이 2개보다 적은 경우

- 데모를 계속 진행하지 말고 사전에 검증한 다른 추천 상품으로 이동한다.
- 결과가 없는 상태를 임의 데이터로 채우지 않는다.

### 에이전트가 `첫 번째 상품`을 잘못 해석한 경우

다음의 명시적 문장으로 한 번만 다시 요청한다.

```text
방금 보여준 첫 번째 상품과 현재 상세 화면의 상품, 이 두 개를 비교해줘.
```

### 로그인 세션이 만료된 경우

- 발표 전에 반드시 로그인 상태를 다시 확인한다.
- 시연 도중 만료되면 우회하지 말고 로그인 필요 안내가 정상적인 보호 동작임을 짧게 설명한다.

### 장바구니에 기존 상품이 남아 있는 경우

- 발표 전에 장바구니를 정리하는 것을 원칙으로 한다.
- 정리하지 못했다면 기존 수량을 먼저 보여주고, 에이전트 실행 후 수량이 증가한 것을 확인한다.

### 주문서 화면에서 결제창이 열릴 위험이 있는 경우

- 주문서 진입 후 추가 입력이나 버튼 클릭을 하지 않는다.
- 최종 멘트가 끝날 때까지 주문서 검토 화면을 유지한다.

## 7. 메인 데모에서 제외하고 질의응답용으로 남길 기능

아래 기능은 구현 가치가 있지만 5분 메인 흐름에서는 보여주지 않는다.

- 피부 타입에 맞는 토너·세럼·크림을 예산 안에서 구성
- 최근 주문과 배송 상태 확인
- 주문 취소 승인
- 실제 구매 상품의 리뷰 초안 작성
- 반품·교환·환불 신청서 작성
- Toss 결제 실행과 주문 완료
- 기간별 구매 이력 요약

질의응답에서 에이전트의 확장성을 질문받으면 다음과 같이 답한다.

> 현재는 비교와 장바구니, 배송지 등록과 주문서 이동뿐 아니라 예산에 맞춘 복수 상품 구성, 주문 상태와 취소, 실제 구매 상품의 리뷰 초안, 반품·교환·환불 신청까지 실제 커머스 API와 연결할 수 있도록 확장돼 있습니다. 오늘은 전체 쇼핑 흐름이 흐트러지지 않도록 가장 대표적인 비교와 실행 장면만 보여드렸습니다.
