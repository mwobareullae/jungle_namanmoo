### 발견 이슈

- ❌ **P0 후보 — 피부검사 제출 실패:** 8문항 완료 후 `Failed to fetch` 원문이 노출되고 결과 화면으로 이동하지 않은 사례가 있음. 같은 API를 직접 호출하면 현재는 200 응답이므로, 실패 시각의 백엔드/RDS 로그 확인이 필요함.
- ❌ **P1 — 모바일 헤더 검색 제출 불안정:** 보이는 검색 버튼이 없고 Enter 암묵 제출에 의존함. 실제 점검에서 Enter로 검색 화면 이동이 되지 않았음.
- ⚠️ **P1 — 비회원 기본 피부 프로필 자동 적용:** 사용자가 선택하지 않았는데 `수부지·보통`이 적용되어 피부 적합도 점수가 계산됨. 의도된 정책인지 확인 필요.
- ❌ **P1 — 검색 결과 중복 상품:** `판테놀` 검색에서 동일 상품이 연속 두 번 표시됨.
- ❌ **P1 — 전성분 중복 표시:** 상품 상세에서 일부 성분이 반복 표시됨.
- ⚠️ **P1 후보 — 가격 조건 오표시:** 가격 조건을 입력하지 않은 추천에서 `가격 조건 반영됨 1.7점`이 표시됨.
- ⚠️ **P1 후보 — 구매 불가 상태 처리:** 백엔드의 `can_purchase=false`가 프론트 구매 버튼을 막지 못할 가능성이 있음.
- ⚠️ **P1 후보 — 찜 목록 페이지네이션:** 프론트가 최초 50개만 읽고 `next_cursor`를 사용하지 않음.
- ✅ **P1 — 회원 전용 피부 프로필 경로 우회 → 수정 완료 (2026-07-21, 배포 전):** 로그인 이력 없는 세션에서 `/signup/skin-profile` 직접 접근 시 회원가입 3단계가 그대로 열리던 문제. [App.tsx](apps/frontend/src/App.tsx)에서 해당 라우트를 `ProtectedRoute`로 감싸도록 수정 (신규 가입 시 2단계에서 이미 세션이 발급되므로 정상 플로우엔 영향 없음). 로컬(localhost:5173)에서 비인증 상태 접근 시 `/login`으로 리다이렉트되는 것 확인. **아직 커밋·배포 전 — 배포 후 mubarelle.com 재확인 필요.**
- ✅ **P2 — 로그인 직후 `/api/me` 401 연속 발생 → 수정 완료 (2026-07-21, 배포 전):** 로그인 성공 후 홈 이동 시 `/api/me`가 401로 여러 번 실패하는 것이 콘솔에 노출되던 문제. [AuthContext.tsx](apps/frontend/src/contexts/AuthContext.tsx)에서 (1) 초기 마운트 시 나가는 `/api/me` 확인 요청이 로그인 완료보다 늦게 응답하면 방금 로그인한 상태를 되돌려 덮어쓸 수 있는 레이스 컨디션, (2) 여러 트리거(초기 마운트·탭 포커스 복귀·다른 탭 로그인 알림)가 겹치면 `/api/me`가 중복 호출되는 구조적 문제를 확인하고, 요청 중복 제거 + 로그인/로그아웃 이후 오래된 응답을 무시하는 generation 가드를 추가. **로컬(localhost:5173) 실제 로그인으로 재검증 완료 — 수정 전 401×3 → 수정 후 로그인 이후 `/api/me` 1회만 호출, 200 OK.** 배포 후 mubarelle.com 재확인 필요.
- ⚠️ **P2 후보 — 로그인 후 헤더에 닉네임과 "로그인" 링크 동시 노출:** 로그인 상태에서도 헤더에 "aa님"과 "로그인" 링크가 함께 표시됨. 반응형 중복 DOM 렌더링 이슈(접근성 섹션 기록)와 연관 가능성 있음, 원인 확인 필요.
- ✅ **P2 — 세션 만료 시 재로그인 안내 없음 → 수정 완료 (2026-07-21, 배포 전):** 프로덕션(mubarelle.com)에서 세션 쿠키 삭제 후 `/mypage` 접근 시 안내 없이 홈으로 이동하는 문제를 확인. [AuthContext.tsx](apps/frontend/src/contexts/AuthContext.tsx)에 세션 만료 플래그(`consumeSessionExpiredFlag`)를 추가하고 [LoginPage.tsx](apps/frontend/src/pages/LoginPage.tsx)에서 "세션이 만료되었습니다. 다시 로그인해 주세요." 토스트를 띄우도록 수정. 로컬(localhost:5173)에서 재현 후 수정 확인 완료. **아직 커밋·배포 전이라 mubarelle.com에는 반영 안 됨 — 배포 후 재확인 필요.**
- ❌ **P2 — 404 없음:** 존재하지 않는 URL에서도 잘못된 URL을 유지한 채 홈페이지가 표시됨.
- ❌ **P2 — 접근성:** 닫힌 장바구니·카테고리 패널이 접근성 트리에 남아 있음.

## 1. 시연 전 P0 점검

- [ ] 홈페이지 첫 진입이 5초 안에 완료된다.
- [ ] 첫 화면에 깨진 이미지·빈 카드·로딩 고착이 없다.
- [ ] 대표 추천 문장을 입력하면 오류 없이 결과가 나온다.
- [ ] 추천 결과 1번 상품 상세가 정상 열린다.
- [ ] 장바구니 추가 후 수량이 즉시 반영된다.
- [ ] 로그인과 로그아웃이 정상 동작한다.
- [ ] 피부검사를 끝까지 제출하고 결과 화면으로 이동한다.
- [ ] 서버 오류 원문, 스택 트레이스, `Failed to fetch`가 사용자에게 노출되지 않는다.
- [ ] 모바일 화면에서 검색·추천·장바구니 핵심 동작이 가능하다.
- [ ] 시연 계정과 시연 데이터가 준비되어 있다.

## 3. AI 맞춤 추천

### 기본 흐름

- [x] `모공이 넓고 트러블이 자주 생겨 고민이에요` 입력 시 고민을 인식한다. `✅ 통과`
- [x] 추천 결과가 생성된다. `✅ 50개 생성`
- [x] 상위 추천 상품 카드가 표시된다. `✅ 상위 10개 표시`
- [ ] 짧은 문장, 긴 문장, 띄어쓰기 오류에서도 동작한다.
- [ ] 고민 하나만 입력했을 때 과도한 조건을 추정하지 않는다.
- [ ] 고민 두 개를 입력했을 때 두 고민이 모두 반영된다.
- [ ] 제품 유형을 입력하지 않았을 때 임의 유형으로 제한하지 않는다.
- [ ] 가격 조건을 입력하지 않았을 때 가격 조건 점수를 표시하지 않는다.
- [ ] 피부 타입을 선택하지 않았을 때 기본 타입 적용 여부를 명확히 알린다.
- [ ] 같은 요청을 반복했을 때 결과가 비정상적으로 흔들리지 않는다.

### 추천 카드·근거

- [ ] 상품명·브랜드·이미지·가격이 서로 맞는다.
- [ ] 동일 상품이 한 추천 결과에 중복되지 않는다.
- [ ] 추천 이유가 질문의 고민과 연결된다.
- [ ] 성분 효능·근거 문구가 실제 연결 데이터와 일치한다.
- [ ] 반려·미검수 근거를 확정 사실처럼 표시하지 않는다.
- [ ] 민감성 위험 상품은 경고 또는 감점이 일관되게 적용된다.
- [ ] 추천 점수 합계와 세부 점수 합계가 일치한다.
- [ ] 추천 결과에서 상품 상세로 이동해도 추천 맥락이 유지된다.

### 예외 입력

- [ ] 빈 입력을 제출할 수 없다.
- [ ] 의미 없는 문자열에 적절한 재입력 안내가 나온다.
- [ ] 이모지·영문·한영 혼용 입력에서도 화면이 깨지지 않는다.
- [ ] 500자 이상 입력 시 제한 또는 안전한 처리가 된다.
- [ ] 욕설·프롬프트 주입성 문장이 서비스 동작을 바꾸지 않는다.
